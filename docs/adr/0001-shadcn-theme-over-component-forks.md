# 0001. Match the Figma design through the theme and call-site classes, not by forking shadcn/ui components

Date: 2026-09-24. Status: accepted.

## Context

The Figma file is built with the official shadcn/ui Figma kit: its colour styles are `base/*`
tokens and Tailwind palette names, its text styles are Tailwind sizes. The task asks to
configure and adapt shadcn/ui components so the UI matches the design.

## Decision

- Colours, radius and the focus ring are set once in `src/app/globals.css` (`--background`,
  `--primary`, `--primary-foreground`, `--ring`), so every component picks them up.
- Layout, spacing and typography are adjusted with Tailwind classes where components are
  used (table cells, pagination footer, page container), never inside `src/components/ui`.
- Variants the design needs and the library lacks are added to the component file as new
  `cva` variants next to the existing ones (`Badge` `success`), without changing existing
  variants.
- Components in `src/components/ui` are otherwise left as generated by the shadcn CLI, so
  they can be re-generated or updated with the CLI at any time.

## Consequences

Two deviations of 2 px are known and accepted: pagination page buttons use the library
radius (10 px, design 8 px) and badges are 20 px tall (design 22 px). Both come from
version drift between the Figma kit and the current shadcn/ui release. Overriding them in
the base components would make the app inconsistent with itself for a 2 px gain.
